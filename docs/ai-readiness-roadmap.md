# AI 医学知识工程路线图

GuidelineOps-CN 当前是 AI 医疗系统的知识治理底座，不是诊疗大模型或临床决策支持系统。它的价值在于：把来源、证据、结构化医学陈述、人工审核和审计记录连接成可追溯闭环，使后续 AI 检索、生成和评测有可控输入。

## 已具备的 AI-ready 能力

| 能力 | 当前实现 | 对 AI 系统的价值 |
| --- | --- | --- |
| 多来源证据采集 | PubMed、Crossref、合法 CSV 导入 | 减少单一来源偏差，保留来源边界 |
| 可追溯性 | 原始响应快照、SHA-256、获取时间、来源链接 | 支持回答溯源、复核和再现 |
| 结构化知识单元 | 原文定位、适用人群、证据等级、推荐强度、中西医映射 | 为 RAG 检索、规则系统和评测集提供最小语义单元 |
| 质量控制 | 缺字段风险、重复候选、确定性报告 | 在进入模型前发现数据缺陷 |
| 人工审核闭环 | 角色分流、白名单、任务状态、追加式审计 | 支持 human-in-the-loop，而非直接相信模型输出 |
| 医学安全边界 | 非临床免责声明、受限来源边界、禁止自动诊疗结论 | 防止将研究工具错误包装为医疗产品 |

## 尚未实现，不应夸大

- 未接入任何 LLM、向量数据库、embedding、RAG 或 Agent。
- 未构建真实患者数据集，不处理 PHI/病历，也不做诊断、处方或剂量计算。
- 未完成医学知识单元的双人复核、版本冻结、撤回影响范围分析和药物安全规则。
- 未建立模型临床评测集、幻觉评估、偏差检测、离线/在线评测或监管验证。

## 推荐开发顺序

### 第一阶段：可信知识资产

1. 版本冻结：批准后生成不可变知识版本，后续修订创建新版本而非覆盖。
2. 撤回与影响分析：来源撤回或医学风险出现时，找出所有受影响知识单元、审核任务和下游导出。
3. 双人复核：高风险用药、中西医映射和推荐陈述要求两名合格审核人独立结论，并支持分歧升级。
4. 药物安全数据契约：只先建立禁忌、特殊人群、相互作用、证据来源和审核状态的结构化模型；不得自动产出处方。

### 第二阶段：检索增强与评测

1. 为**已批准且未撤回**的知识版本建立检索索引，检索结果必须返回 `unit_id`、来源定位、版本和审核状态。
2. 建立带标准答案、证据定位和不可回答类别的评测集；优先评估可溯源率、拒答率、版本一致性和高风险错误率。
3. 让模型只能基于检索到的批准知识生成“研究性摘要”，无证据时明确拒答或要求人工复核。
4. 将模型输出、检索证据、提示词版本、模型版本和人工判定一并记录，形成评测—反馈—改进闭环。

### 第三阶段：受控产品化

1. 引入正式身份认证、细粒度权限、数据库迁移、备份恢复和监控告警。
2. 由医学、药学、方法学、产品和研发共同定义变更控制、风险分级、验收阈值与升级机制。
3. 在法律、隐私、信息安全和监管评估完成前，不将系统用于真实临床决策。

## 面试时的准确说法

可以说：“我做的是面向医疗 AI 的证据与知识治理层，重点不是直接调用大模型，而是先解决指南来源追溯、结构化知识单元、审核分流、审计闭环和中西医映射的可信输入问题。这个底座可继续承接 RAG、模型评测和人机协同审核。”

不要说：“我已经开发了临床诊疗大模型”或“项目已用于辅助诊疗”。
