# AI 医学知识工程路线图

GuidelineOps-CN 当前是面向 AI 医疗系统的知识治理底座，不是诊疗大模型或临床决策支持系统。项目价值在于把来源、证据、结构化医学陈述、人工审核和审计记录连接成可追溯闭环，为后续检索增强、规则系统和模型评测提供受控输入。

## 已具备的 AI-ready 能力

| 能力 | 当前实现 | 对 AI 系统的价值 |
| --- | --- | --- |
| 多来源采集 | PubMed、Crossref、合法 CSV 导入 | 降低单一来源偏差，保留来源边界 |
| 可追溯性 | 原始快照、SHA-256、获取时间和来源链接 | 支持回答引用、复核和再现 |
| 结构化知识 | 原文定位、适用人群、证据等级、推荐强度、中西医映射 | 为 RAG、规则和评测集提供最小语义单元 |
| 质量控制 | 缺字段风险、重复候选、确定性质量报告 | 在进入模型前发现数据缺陷 |
| 人工审核闭环 | 角色路由、并发认领、双人复核、分歧升级和不可变审计 | 支持 human-in-the-loop，而非直接信任模型输出 |
| 医学安全边界 | 非临床免责声明、来源约束、禁止自动诊疗结论和剂量指令 | 防止研究工具被误包装成医疗产品 |

## 尚未实现，不应夸大

- 尚未接入 LLM、向量数据库、embedding、RAG 或 Agent。
- 尚未建立真实患者数据集，不处理 PHI/病历，也不做诊断、处方或剂量计算。
- 尚未完成系统性的临床盲评、幻觉评估、偏差检测、离线/在线评测或监管验证。
- 尚未完成正式身份认证、细粒度权限、数据库迁移、通知告警和灾备演练。

## 推荐开发顺序

### 第一阶段：可信知识资产

1. 对批准内容生成不可变知识版本，后续修订创建新版本而不是覆盖旧版本。
2. 来源撤回或医学风险出现时，找出受影响知识单元、审核任务和下游导出。
3. 高风险用药、中西医映射和推荐陈述必须经过两名合格审核人；意见分歧升级到 `medical_chair`。
4. 持续补充规范术语、来源版本、基层可及性和国家基本药物目录映射，但不自动生成处方。

### 第二阶段：检索增强与评测

1. 只对已批准且未撤回的知识版本建立索引，检索结果必须返回 `unit_id`、来源定位、版本和审核状态。
2. 建立带标准答案、证据定位和不可回答类别的评测集，优先评估可溯源率、拒答率、版本一致性和高风险错误率。
3. 模型只能基于检索到的批准知识生成研究性摘要；证据不足时必须拒答或要求人工复核。
4. 保存模型版本、提示词版本、输入知识快照、检索证据、输出和人工判定，形成评测—反馈—改进闭环。

### 第三阶段：受控产品化

1. 引入正式身份认证、细粒度权限、数据库迁移、备份恢复和运行监控。
2. 由医学、药学、方法学、产品和研发共同定义变更控制、风险分级、验收阈值和升级机制。
3. 在法律、隐私、安全和监管评估完成前，不将系统用于真实临床决策。

## 面试时的准确表述

可以说：“我做的是面向医疗 AI 的证据与知识治理层，先解决指南来源追溯、知识结构化、医学审核和中西医映射的可信输入问题；这套底座可以继续承接 RAG、模型评测和人机协同审核，但当前项目本身不宣称已经完成临床验证，也不直接输出诊断或处方。”
