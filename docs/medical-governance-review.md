# 医学治理与临床安全补充审查

## 目的与审查范围

本审查面向 AI 医学经理（中西医方向）的岗位要求，检查 GuidelineOps-CN 是否已经从“可追溯的指南元数据管道”迈向“可受控的医学知识治理系统”。审查对象包括 `SourceRecord`、质量报告、SQLite 审核队列、来源适配器和现有 README/规格文档。

本项目当前定位为研究与教育用途的元数据治理工具，不是医疗器械、CDSS 或处方系统。下文提出的是治理要求和未来实现规格，不代表当前版本已经具备临床决策能力。

## 当前已经具备的治理基础

- 来源响应保留原始快照、抓取时间和 SHA-256，可追溯到来源层。
- PubMed/Crossref 与用户导出的 CNKI/万方元数据被区分处理，未绕过登录、验证码或付费全文。
- DOI/PMID 去重是保守候选机制，不自动删除或合并记录。
- 质量报告只产生风险信号，不自动宣称医学有效。
- 审核任务与原始记录分离，领取、结论和系统同步均产生审计事件。
- README 已声明研究/教育用途和不得用于真实临床决策。

这些设计体现了“证据链优先、人工复核、不可逆操作最小化”的正确方向，但仍主要停留在书目元数据层。

## 主要不足与风险

### 1. 来源等级和证据强度尚未结构化

`document_type` 只能区分 guideline、consensus、standard 等粗粒度类型，不能回答以下临床治理问题：

- 发布机构是否为国家卫生行政部门、专业学会、医院或商业主体；
- 是否有正式方法学（GRADE、AGREE II、Delphi 等）和证据检索流程；
- 推荐强度、证据质量、结局指标和适用人群是什么；
- 同一疾病的指南、共识、标准和综述之间谁具有优先级；
- 是否已被修订、撤回、替代或超过有效期。

没有这些字段，质量报告无法区分“元数据完整”与“临床证据可信”。

### 2. 审核队列仍是元数据审核，不是医学内容审核

当前队列的信号来自缺年份、缺 URL、缺 DOI/PMID 和标题重复候选。它可以发现“记录不完整”，但不能覆盖：

- 推荐是否被原文准确转录；
- 禁忌、剂量、疗程和特殊人群限制是否完整；
- 中医证候、治法、方药与西医疾病/诊断的映射是否由合格人员确认；
- 指南之间冲突时是否记录冲突及其处理依据；
- 证据是否适用于基层医疗资源和国家基本药物目录。

因此，`approved` 只能表示“该审核任务的结论”，不得被解释为“文献或临床建议已验证”。

### 3. 审核角色、资质和双人复核规则缺失

审核命令现要求同时填写 `--reviewer` 与 `--role`；元数据缺项和重复候选会携带风险等级、所需角色及“是否需要医学审核”的机器可读分流信息，角色不匹配时不能认领或作出结论，审计事件会记录所声明的角色。部署方还可配置本地审核人员白名单，拒绝未被授予该角色的 ID。该机制只保证工作流授权，仍不验证执业医师资格、专业方向、机构和权限；也没有医学编辑、药学安全审核、方法学审核和最终医学负责人之间的职责分离。

高风险知识单元现已采用双人审核：医学审核员初审通过后自动创建医学负责人终审任务，初审人与终审人不能为同一审核人；只有终审通过才更新知识单元为 `approved`。这仍是工作流控制，不替代资质验证。对处方剂量、禁忌、孕哺期、儿童、肝肾功能不全、急危重症等内容，后续还应支持不同结论的正式分歧升级，而不是由最后一次 CLI 操作覆盖结论。

### 4. 中西医知识边界没有显式建模

当前 `disease_tags` 是自由文本，不能表达：

- 西医疾病、症状、体征、检查和严重程度；
- 中医病名、证候、治法、方剂、药味和证候演变；
- “中医证候 ≠ 西医疾病”的非一一对应关系；
- 映射依据、适用条件、证据来源和禁止外推范围。

如果后续直接把自由文本送入大模型，容易产生“证候等同疾病”或把经验方包装成循证推荐的错误。

### 5. 用药安全和基层场景尚未成为一等公民

项目尚无药品成分、剂型、剂量单位、给药途径、疗程、禁忌、相互作用、肝肾功能调整、妊娠哺乳、儿童/老年人和过敏史等字段，也没有国家基本药物目录、基层可及性或医保限制的版本化来源。

在缺少这些约束时，系统不得生成“推荐用药”“替代药物”“可报销”等结论；后续若增加药物规则，必须把“缺少患者关键信息”视为阻断条件，而不是让模型猜测。

### 6. 临床安全事件和知识撤回机制不足

知识单元已支持由医学负责人执行撤回、保留不可修改的撤回原因，并基于中西医映射找出受影响的下游知识单元；终审通过后可保存带 SHA-256 的不可修改版本快照。仍不能影响真实 AI 输出、暂停下游消费或完成通知闭环。对于发现严重禁忌遗漏或来源撤回，后续应扩展为安全事件，记录谁在何时确认、修订和重新发布。

## 建议的治理数据契约（后续版本）

建议在不破坏现有 `SourceRecord` 的前提下，新增独立的医学知识单元和审核结论表，而不是把临床语义继续塞入 `metadata` 自由 JSON。

### 来源与证据层

| 字段 | 说明 | 最低要求 |
|---|---|---|
| `issuer` | 发布机构及机构类型 | 必填；机构类型可枚举 |
| `jurisdiction` | 国家/地区、适用卫生系统 | 必填 |
| `publication_status` | active、superseded、withdrawn、unknown | 必填 |
| `version` / `effective_from` / `effective_to` | 版本和有效期 | 尽量必填 |
| `methodology` | GRADE、AGREE、Delphi 等 | 未知时显式 unknown |
| `evidence_grade` | 证据质量等级 | 只能引用原文或标记 not_reported |
| `recommendation_strength` | 强/弱或原文等价表达 | 不允许模型推断 |
| `conflict_of_interest` | 利益冲突声明及审查状态 | 缺失需风险标记 |
| `population` / `setting` | 人群、基层/专科、资源条件 | 必填或 unknown |

### 中西医知识层

每个知识单元应带 `unit_id`、`source_record_id`、原文定位（页码/章节/表格）、结构化陈述、适用条件、排除条件、证据等级和审核状态。中医字段至少区分病名、证候、治法、方药；西医字段至少区分疾病、症状、检查、诊断和治疗。映射关系应有 `mapping_type`（等价、相关、条件映射、不可映射）和独立审核结论。

### 用药安全层

药物规则不能只存自然语言提示。建议结构化为：成分、剂型、剂量与单位、途径、疗程、适应证、禁忌证、相互作用、特殊人群、肝肾调整、基层可及性、来源版本和生效日期。任何缺少来源定位或患者必要信息的规则，只能输出“需要人工核验”，不得输出肯定式治疗建议。

## 审核角色和职责矩阵

| 角色 | 可执行工作 | 不得单独执行 |
|---|---|---|
| 数据审核员 | 来源、标识符、版本、链接和重复候选 | 认可临床推荐或药物安全性 |
| 中医医学审核员 | 证候、治法、方药和中医术语映射 | 将证候直接等同西医疾病 |
| 西医医学审核员 | 疾病定义、诊断、检查、推荐强度 | 擅自改写中医理论或经验内容 |
| 药学/用药安全审核员 | 剂量、禁忌、相互作用、特殊人群 | 在患者信息缺失时给出个体化处方 |
| 方法学审核员 | 证据等级、检索方法、利益冲突、版本 | 代替临床专家判断具体病例 |
| 医学负责人 | 冲突裁决、发布/撤回、风险升级 | 绕过来源定位和审计记录 |

高风险规则应至少经过一名相应专业审核员和一名医学负责人复核；分歧、来源撤回或严重安全信号应自动进入升级队列。

## 对 AI/LLM 的硬性安全边界

后续任何摘要、抽取或问答模块都必须：

1. 强制返回来源记录、原文定位、版本和证据等级；找不到定位时返回“不足以判断”。
2. 将“原文陈述”“结构化转录”“模型推断”分栏保存，禁止混成一段推荐话术。
3. 不根据症状直接开方、给剂量、替代药物或判断医保报销。
4. 对急危重症、孕哺期、儿童、老年人、肝肾功能异常和多重用药触发人工升级。
5. 对中西医映射明确提示其非等价性，并展示反例/排除条件。
6. 保留模型版本、提示词版本、输入知识快照、输出和人工修改记录，支持回放与偏差分析。

## 推荐实施顺序

### P0：先补治理规则（不改变临床能力）

- 将“审核任务已通过”与“医学知识已批准”分成不同状态命名。
- 在质量报告中增加来源等级、版本缺失、利益冲突缺失和适用场景缺失风险（初期可以只做字段与规则）。
- 已为现有元数据任务增加风险等级和所需角色；后续高风险任务必须禁止单人直接关闭。
- 固定研究/教育用途、非医疗器械、非处方和非医保判断免责声明。

### P1：建立知识单元审核闭环

- 新增知识单元、证据陈述、映射关系和药物安全规则表。
- 支持原文定位、版本冻结、双人复核、冲突升级、撤回和影响范围报告。
- 为每种中西医映射和推荐陈述提供可复核测试夹具。

### P2：再考虑模型和产品化

- 在有足够人工标注集后评估抽取准确率、漏报率、冲突识别率和分层召回率。
- 通过脱敏离线评测验证模型，不将真实患者数据写入当前元数据数据库。
- 在身份认证、权限、并发控制和变更审批到位前，不开放临床生产使用。

## 验收标准

未来实现至少应通过以下治理检查：

- 每条临床陈述都能定位到来源、版本和原文位置，未知字段显式标记而非猜测。
- `approved` 的含义仅限于指定角色对指定知识单元/任务的审核结论。
- 高风险药物和中西医映射任务具备双人复核和冲突升级记录。
- 来源撤回或版本过期能够阻断下游消费并生成影响范围清单。
- 任何模型输出均可回放到输入快照、提示词版本和人工修订事件。
- 所有真实临床决策、处方、医保结论和患者个案仍明确排除在项目范围之外。
