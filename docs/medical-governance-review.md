# 中西医 AI 知识治理审查

更新时间：2026-08-21

本文从医学安全、证据治理和研发协作角度审查 GuidelineOps-CN。当前系统是研究/教学用途的知识工程原型，不是诊疗系统；`approved` 只代表指定审核流程完成，不代表临床有效。

## 一、当前已实现的治理能力

### 来源与证据

- PubMed、Crossref 和用户合法导出的 CNKI/万方 CSV 进入统一来源记录。
- 原始响应保存快照、获取时间和 SHA-256；知识单元必须提供来源记录和原文定位。
- 知识单元包含领域、陈述、适用条件、证据等级、推荐强度、版本和审核状态。
- 中西医映射显式区分等价、相关、条件映射和不可映射，不能把证候直接等同于西医疾病。

### 审核与责任

- 高风险知识先由 `medical_reviewer` 初审，再由不同的 `medical_lead` 终审。
- 终审驳回会保留 `pending` 状态并创建 `knowledge_escalation`，交由 `medical_chair` 裁决；用药安全规则同理创建 `medication_safety_escalation`。
- 审核任务具备风险等级、所需角色、医学审核标记、并发认领保护和追加式审计事件。
- 撤回记录不可修改；批准版本可冻结为带 SHA-256 的不可变快照，并能分析映射依赖的影响范围。

### 用药安全边界

当前安全规则覆盖禁忌证、相互作用、特殊人群、器官功能受损、监测和停药。规则必须引用来源知识单元；系统拒绝剂量和患者个体化处方指令。缺少来源定位、关键患者信息或适用范围时，只能进入人工核验，不得输出肯定式治疗建议。

## 二、仍需补齐的医学治理字段

建议逐步补充以下一等字段，并纳入审核门禁：

| 领域 | 需要结构化的信息 |
| --- | --- |
| 来源质量 | 发布机构、司法辖区、版本、生效/失效日期、方法学、利益冲突、更新状态 |
| 证据强度 | GRADE/AGREE/Delphi 等方法、证据等级、推荐强度、原文限制 |
| 适用范围 | 人群、基层/专科场景、资源约束、排除条件和急危重症边界 |
| 中西医映射 | 疾病、症状、证候、治法、方药、检查及映射证据；明确不可映射关系 |
| 用药安全 | 成分、剂型、途径、禁忌、相互作用、孕哺期、儿童、老年、肝肾功能和监测要求 |
| 基层可及性 | 基本药物目录、医保政策的适用地区和生效时间；不得把缺失信息当成可报销结论 |
| 审核责任 | 审核人资质、专业角色、利益冲突、双人独立性、升级原因和裁决记录 |

## 三、医学审核角色矩阵

| 角色 | 可以负责 | 不得单独负责 |
| --- | --- | --- |
| 数据审核员 | 来源、标识符、版本、链接和重复候选 | 临床推荐或用药安全结论 |
| 中医审核员 | 证候、治法、方药和中医术语映射 | 将证候直接等同西医疾病 |
| 西医审核员 | 疾病定义、诊断、检查和治疗证据 | 擅自改写中医理论或经验 |
| 药学/用药安全审核员 | 禁忌、相互作用、特殊人群和器官功能风险 | 患者信息缺失时给出个体化处方 |
| 方法学审核员 | 证据等级、检索方法、利益冲突和版本 | 代替临床专家判断具体病例 |
| 医学负责人 | 冲突裁决、发布、撤回和风险升级 | 绕过来源定位和审计记录 |

高风险规则至少需要一名相应专业审核员和一名医学负责人复核。终审分歧、来源撤回和严重安全信号必须进入升级或安全事件队列。

## 四、对 AI/LLM 的硬性边界

任何后续摘要、检索或问答模块都必须：

1. 返回来源记录、原文定位、版本和证据等级；找不到定位时返回“证据不足以判断”。
2. 分开保存原文陈述、结构化转录和模型摘要，不能混成一段无来源的推荐话术。
3. 不根据症状直接开方、给剂量、替代药物或判断医保报销；涉及急危重症、孕哺期、儿童、老年、肝肾异常和多重用药时升级人工复核。
4. 明确中西医映射不是天然等价关系，并展示排除条件和不确定性。
5. 记录模型版本、提示词版本、输入知识快照、检索证据、输出和人工修改，支持撤回和偏差分析。

## 五、优先级

### P0：共享环境前

- 接入组织身份和权限管理，禁止 PHI/PII 进入公开仓库和日志。
- 建立数据库迁移、备份恢复、访问控制、日志监控和告警。
- 将审核角色白名单从示例配置升级为管理员维护的受控配置。

### P1：医学资产形成前

- 补齐来源方法学、利益冲突、适用人群、版本有效期和基层场景字段。
- 建立中西医术语表、映射证据和不可映射规则。
- 建立药物安全术语、来源版本冻结、撤回影响分析和基本药物目录映射。
- 建立盲评集、错误分级、召回机制和下游 AI 输出影响分析。

### P2：受控产品化

- 建立通知闭环、变更审批、模型评测、运行监控和安全事件响应。
- 在完成临床验证、隐私安全和监管评估前，不得用于真实临床决策。
