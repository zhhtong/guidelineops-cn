# GuidelineOps-CN 上线前核对清单

更新时间：2026-08-21

这份清单区分“研究/教育用途可用”和“临床生产可上线”。项目测试通过不等于已经获得医疗器械、临床决策支持或执业资质意义上的批准。

## 当前结论

| 场景 | 状态 | 说明 |
| --- | --- | --- |
| 本地研究/教育 | 可用 | 可运行采集、导入、质量报告和人工审核队列 |
| 受控内网试用 | 有条件可用 | 应配置审核人员白名单、备份目录和最小权限账号 |
| 对外公开 GitHub | 代码层面接近就绪 | 仍需配置远程仓库、检查仓库设置并启用安全功能 |
| 临床生产/CDSS | 不可上线 | 尚无知识单元、临床验证、监管质量体系和正式身份权限系统 |

## 已验证项目

- `uv run pytest -q`：当前测试全部通过。
- `uv run ruff check .`、`uv lock --check`、`git diff --check`：通过。
- `uv build`：源码包和 wheel 均可构建。
- CLI 帮助、审核角色分流、并发认领、审计不可变性和审核人员白名单均有测试覆盖。
- 来源原始响应保存 SHA-256、数据库记录与审核事件可追溯。
- CNKI/万方仅接受合法用户导出的 CSV，不绕过验证码或受限内容。

## 上线前必须补齐

### P0：进入任何共享环境前

1. **身份与权限**：把本地 JSON 白名单替换为组织身份源或受控服务账号；审核角色不能由用户自报，至少要有管理员维护、变更记录和离职撤权流程。
2. **数据保护**：禁止 PHI/PII 进入公开仓库和日志；确定数据库、原始响应和审核事件的访问控制、保留期限、加密与删除流程。
3. **备份恢复**：建立 SQLite/导出文件的定期备份、校验和恢复演练；仅复制文件不算验证过的灾备。
4. **数据库演进**：引入 Alembic 或等价迁移机制，给 schema 版本、升级、回滚和备份前置检查；`create_all` 只适合初始化。
5. **运行监控**：为 PubMed/Crossref 请求失败、限速、快照写入失败、数据库锁和审核队列积压建立结构化日志、指标和告警。

### P1：形成医学知识资产前

1. **知识单元模型**：当前已有可校验的数据契约、导入/提交/查询 CLI、医学初审—医学负责人终审的双人流程、撤回记录、映射依赖影响分析，以及审批后的 SHA-256 版本冻结；仍需正式分歧升级和下游 AI 输出影响分析。
2. **中西医映射**：独立建模疾病、症状、检查、证候、治法、方药及“等价/相关/条件映射/不可映射”关系，禁止把证候直接等同西医疾病。
3. **用药安全**：当前已建立禁忌、相互作用、特殊人群、器官功能受损、监测和停药的高风险规则模型，并要求双人复核；仍需规范术语、来源版本冻结、撤回影响分析、基层可及性和国家基本药物目录映射。项目不得做剂量或个体化处方推断。
4. **医学验证**：定义盲评集、错误分级、召回/撤回、影响范围和变更审批；`approved` 只能表示指定任务完成审核，不表示临床有效。

### P2：公开发布与长期维护

1. **GitHub 发布**：创建真实远程仓库后再推送；补充仓库 URL、发布标签、变更日志和维护者联系方式。
2. **供应链安全**：为 GitHub Actions 固定 commit SHA 或建立定期升级流程，启用 Dependabot/secret scanning/code scanning（按组织计划可用性配置）。
3. **质量门禁**：把构建、测试、锁文件校验、安全扫描和文档链接检查纳入 CI；可考虑加入覆盖率阈值，但先定义合理基线。
4. **适配器可持续性**：记录每个来源的许可、API 条款、速率限制和字段变更；网络失败应局部降级并保留可诊断错误，而不是让整批发现任务静默丢失。

## 试用环境最小操作流程

```bash
uv sync --locked
cp reviewers.example.json reviewers.local.json
export REVIEWER_REGISTRY_PATH=reviewers.local.json
uv run guidelineops --help
uv run pytest -q
uv run guidelineops review-sync
uv run guidelineops review-list --status open
```

试用前应把 `reviewers.local.json` 放在私有配置目录，不提交到 Git；审核人员 ID 应使用组织内部稳定标识，而不是在仓库中保存证件号码或密码。

## 明确禁止的上线表述

- 不得称项目“已通过临床验证”“可直接辅助诊断”或“已满足医疗器械监管要求”。
- 不得把来源元数据审核任务当作医学知识审核结果。
- 不得把角色白名单当作执业医师资格、机构认证或患者授权。
- 不得把通过 CI、构建成功或拥有 GitHub stars 当作临床安全证据。
