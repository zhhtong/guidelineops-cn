# GuidelineOps-CN 上线前检查清单

更新时间：2026-08-21

本文区分“研究/教学环境可用”和“临床生产环境可上线”。测试通过不等于医疗器械批准、临床决策支持资格或执业资质验证。

## 当前结论

| 场景 | 状态 | 说明 |
| --- | --- | --- |
| 本地研究/教学 | 可用 | 可运行采集、导入、质量报告和人工审核队列 |
| 受控内网试用 | 有条件可用 | 需要配置审核人员白名单、备份目录和最小权限账户 |
| GitHub 公开代码 | 代码层面接近就绪 | 仍需配置真实远程仓库并启用仓库安全功能 |
| 临床生产/CDSS | 不可上线 | 尚无临床验证、正式身份权限体系和监管评估 |

## 已验证

- `uv run pytest -q`：本地测试全部通过。
- `uv run ruff check .`、`uv lock --check`、`git diff --check`：通过。
- `uv build`：源码包和 wheel 均可构建。
- CLI 帮助、审核角色路由、并发认领、审计不可变性和审核白名单有测试覆盖。
- 原始响应保存 SHA-256、数据库记录与审核事件可追溯。
- CNKI/万方仅接受用户合法导出的 CSV，不绕过验证码或受限内容。

## 共享或上线前必须补齐（P0）

1. **身份与权限**：把本地 JSON 白名单替换为组织身份源或受控服务账号；审核角色必须由管理员维护，并有变更和离职撤权记录。
2. **数据保护**：禁止 PHI/PII 进入公开仓库和日志；为数据库、原始响应和审核事件配置访问控制、保留期限、加密和删除流程。
3. **备份恢复**：建立 SQLite/导出文件的定期备份、校验和恢复演练，不能只复制文件而不验证恢复结果。
4. **数据库演进**：引入 Alembic 或等价迁移机制，记录 schema 版本、升级、回滚和备份前置检查；`create_all` 只适合初始化。
5. **运行监控**：为 API 失败、限速、快照写入失败、数据库锁和审核队列积压建立结构化日志、指标和告警。

## 形成医学知识资产前（P1）

1. 知识单元已有来源定位、证据等级、双人复核、终审分歧升级到 `medical_chair`、撤回、影响分析和 SHA-256 冻结；仍需通知闭环和下游 AI 输出影响分析。
2. 中西医映射已有条件映射和依赖影响模型；仍需由中医、西医和方法学人员共同定义术语表、映射证据和不可映射规则。
3. 用药安全规则已覆盖禁忌、相互作用、特殊人群、器官功能受损、监测和停药；仍需规范术语、来源版本冻结、撤回影响、基层可及性和国家基本药物目录映射。
4. 建立盲评集、错误分级、召回/撤回、影响范围和变更审批；`approved` 只表示指定审核流程完成，不表示临床有效。

## 公开发布与长期维护（P2）

1. 创建真实 GitHub 远程仓库，补充仓库 URL、版本标签、变更日志和维护者联系方式。
2. 为 GitHub Actions 固定 commit SHA 或建立定期升级流程，按组织条件启用 Dependabot、secret scanning 和 code scanning。
3. 将构建、测试、锁文件校验、安全扫描和文档链接检查纳入 CI。
4. 为每个来源适配器记录许可、API 条款、速率限制、字段变化和网络失败降级策略。

## 最小受控试用流程

```bash
uv sync --locked
cp reviewers.example.json reviewers.local.json
export REVIEWER_REGISTRY_PATH=reviewers.local.json
uv run guidelineops --help
uv run pytest -q
uv run guidelineops review-sync
uv run guidelineops review-list --status open
```

审核白名单应放在私有配置目录，不提交到 Git；审核人 ID 使用组织内部稳定标识，不保存证件号码或密码。

## 明确禁止的上线表述

- 不得称项目“已通过临床验证”“可直接辅助诊断”或“已满足医疗器械监管要求”。
- 不得把元数据审核任务当作医学知识已经有效，也不得把角色白名单当作执业资格证明。
- 不得因为 CI 通过、构建成功或获得 GitHub stars 就宣称临床安全。
